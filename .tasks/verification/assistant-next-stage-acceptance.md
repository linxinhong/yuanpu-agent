# 助理下一阶段验收：云端、平台与长期语义

2026-09-27 基线：main `4baed6f`。本记录是验收设计与 `jump` 的只读环境取证，不是云端同步或跨平台、长期语义通过的结果。既有本机闭环见[独立助理完整业务验收（TASK-050）](TASK-050/results.md)；云端所有权与来源边界以[助理设计](../../docs/assistant-memory-proposal.md#本地先行与云端迁移边界)为准。当前“其他平台”指 Windows/Linux 桌面及 Linux 云端宿主；飞书、微信、钉钉仍按既定范围暂缓。

## 已观察到的条件

- `ssh jump` 可用；目标为 Alibaba Cloud Linux 3、x86_64、glibc 2.32，2 vCPU、约 1.8 GiB RAM，系统盘尚余约 22 GiB。当前 SSH 用户的 home 权限为 0700，用户级 systemd 可用；80/443 已有服务监听，不应占用或改动。
- VM 当前无 Node、pnpm、uv、git，也无 Yuanpu 部署。Docker 客户端存在，但当前 SSH 用户无 Docker socket 权限。Python 为 3.6.8。仓库当前只有 macOS arm64 本地产物；需要取得适配该机器的 Linux x64 Runtime/Worker 制品，并在目标机核对动态链接、启动和内存占用。不能拿 macOS 构建或 CI 的 Linux 探针结果代替这台机器的运行结果。
- [App 多入口与升级完整业务验收（TASK-021）](TASK-021/results.md)曾在 Linux/Windows runner 通过**助理落地前**的打包桌面探针；[独立助理完整业务验收（TASK-050）](TASK-050/results.md)在 macOS arm64 通过助理打包旅程及一次获授权的企微私聊。两者都不证明新助理在 Windows/Linux 运行，也不证明跨网络同步或长期语义质量。
- `packages/yuanpu-assistant`、`apps/runtime/src/assistant-worker.ts` 与来源/记忆契约已提供本地单写入、来源版本和撤回接缝；网络同步、远程身份认证、常驻云端宿主均尚未实现。`packages/evals` 是 Pi Coding Agent 的离线评测方法参考，不作为助理运行时依赖。

## 验收分层与判定

| 门槛 | 必须观察到的结果 | 执行环境和证据 | 当前判定 |
| --- | --- | --- | --- |
| 云端来源同步 | 两个独立设备身份以授权范围上传同一批合成 Work 来源；接收方按稳定 ID/版本/受众读取正文或受控产物快照。断网重连、重复/乱序提交、上传中断、来源撤回与遗忘后，云端最终只含最新有效版本；撤回后模型输入不得复活旧事实。每个提交有持久 ACK 和可查询游标，失败有明确积压/重试状态。 | 临时本地 Home + `jump` 隔离数据目录；记录源/云事件数、版本、ACK、队列与模型输入的脱敏摘要，注入断网/重启。不能用复制运行中的 SQLite/JSONL 或仅比对文件数量代替。 | 未实现、未验证 |
| 云端权威与迁移 | 云端只运行一个可写 Assistant Worker；本地切为来源/客户端，不能继续写第二个助理 Home。桌面与企微仍共享个人记忆但聊天 Session 独立；关闭桌面后云端按宿主策略继续，恢复桌面后可看到同一状态。迁移前后备份可恢复、旧端停写、凭据单独配置，错误身份/设备拒绝。 | 先用合成账号/来源在 `jump` 运行，再做经过范围确认的真实迁移；检查进程、写锁、会话/队列状态、恢复演练与客户端重连。企微信息往返单列真实收件证据，不能由本机旧记录推断。 | 未实现、未验证 |
| Linux/Windows 助理 | 各目标平台的打包 App/SEA 能启动 Runtime 与 Assistant Worker、初始化七项专属技能、建 Work 后整理并在助理侧读取、修订/遗忘/撤回、重启持久、完整退出回收子进程。至少 Linux VM 上实跑无界面 Worker/SEA；Linux GUI 用 Xvfb/目标桌面，Windows 用目标 runner/机器验证真实打包旅程。 | 同一源码 revision 的制品 SHA、平台/架构、打包命令、临时 Home、探针日志和逐场景结果；标明合成模型、真实模型和真实渠道各自范围。`jump` 的 Linux 成功不能证明 Windows。 | 助理专属平台验收未执行 |
| 长期语义 | 助理能从多轮 Work 与助理对话中形成有来源的用户理解、项目/承诺状态；能处理矛盾、纠正、遗忘、来源消失、跨会话隔离和时间衰减；工作评估不把模型自述当完成，建议有证据且时机合适。 | 冻结合成/获许可语料、盲测标签、模型/提示词版本、回放时钟与 30/90 天节点；真实模型至少三次重复。另做跨自然日观察，记录用户对建议的有效/无用反馈，不能用虚拟时钟冒充长期使用。 | 未建立离线语义基准或纵向观察 |

云端验收先以合成数据完成故障注入和恢复，再迁移真实资料；每次只保留最小化脱敏证据。若出现双写、越权、撤回后复活或不可恢复的数据损失，相关门槛直接失败并停止真实迁移。其他失败记录为 `fail`，环境或凭据缺失记录为 `unverified`，不将构建通过记成业务通过。

语义门槛在首次评测前锁定评分规则和 holdout。建议的首轮硬约束：纠正、遗忘、越权与“无证据却宣称完成”场景必须全部通过；带来源的个人事实准确率至少 95%，应记住的明确偏好召回至少 85%；在至少 30 个有/无建议机会的盲审样本上，适时且可行动的建议占已提出建议至少 70%，无新证据时的打扰率不高于 10%。同时报告分母、置信区间、按情境拆分的失败和成本/延迟；不能以总体均值掩盖严重个案。阈值是进入实施前的初版验收契约，基线运行后不得用测试结果倒改阈值。
