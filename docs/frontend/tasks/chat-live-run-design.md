# 工作对话实时过程与 Pi Session 轨迹设计

状态：交互与视觉设计基线，2026-09-27。以 [Yuanpu 现有 1440×900 工作界面](../evidence/task-059/tree-light.png) 为视觉基线；选定图为 [v003 当前 Pi Session 轨迹](../design/chat-live-run/design-v003-session-trajectory.png)与 [v004 上下文按钮及子智能体 Viewer](../design/chat-live-run/design-v004-context-button.png)。先前 [v001](../design/chat-live-run/design-v001-run-trace.png) 把轨迹简化为一次运行的事件列表，[v002](../design/chat-live-run/design-v002-subagent-context.png) 在上下文弹层加入轨迹页签，均已由用户修正，仅作历史草稿。产品实现位于 Yuanpu protocol、runtime、desktop 与 app；图中会话、事件、模型与 token 数字都是安全示例，精确行为以本文为准。

## 目标与现状

用户在工作对话提交任务后，应立即看到 Agent 的文字增量和实际发生的操作。右侧「运行轨迹」要像所给参考图一样，呈现**当前工作对话绑定的整个 Pi Session 活动分支**：多轮用户输入、助手消息、工具调用及结果、模型与上下文事件，包含概览时间轴和可检索的逐行记录；子智能体另有独立过程 Viewer。当前 `ChatPanel.observeRun` 每 900 ms 获取一次运行状态，终态后才追加完整回复与工具摘要；Pi 会话内部已有 `message_update.text_delta`、`tool_execution_start/end` 等实时事件，但 Yuanpu 适配层只在内存累积它们。右侧既有「动态」「运行」表达了两套不完整的运行信息。

参考边界：`deepseek-harness` 的 `TurnProcessNodeView`、`ToolRow` 使用紧凑折叠过程与单行工具摘要；`zcode` 的 `ModelSelect`、`contextUsage`、`ModelTrajectoryPane` 和 `SubagentSessionSidePane` 分别提供输入区控件、轨迹与子会话 Viewer 的可借鉴交互。只取交互原则，保留 Yuanpu 现有工作树、消息宽度、输入卡片、浅色/深色 token 和右栏单层标签条。

检索：Yuanpu 工作区以 ZG 查询聊天运行事件、右栏及 telemetry 关系，命中 `chat.tsx`、Pi 适配层和 telemetry 文档；再用 scoped `rg` 核对确切接口。两个参考仓库的 ZG 索引均缺失，未创建索引；以 scoped `rg` 和目标组件读取核实上述行为。

## 页面结构

```text
现有：左侧图标栏 │ 工作树 │ 中央对话与底部输入卡片 │ 右侧文件/浏览器标签 Viewer
变更：保持以上四列几何与样式；只在中央消息内增加“运行过程”，在输入卡片
      右下增加“模型 / 上下文圆环 / 发送”，在右侧同一标签条增加两个 Viewer。
```

右侧原有「动态」「运行」标签及其内容移除，由两个互不重复的 Viewer 取代：

| Viewer | 顶部标签与主要内容 | 从哪里进入 |
| --- | --- | --- |
| 运行轨迹 | 当前 Pi Session 活动分支的全程记录；顶部「时长 / 轮次 / 调用」概览、搜索与筛选，下方按会话顺序显示输入、助手、工具、上下文等行，工具行可展开调用与结果 | 对话中的运行过程、上下文弹层的「打开运行轨迹」按钮、右侧 `+` 菜单 |
| 子智能体 | 本次及历史子智能体列表，显示名称、任务摘要、状态、开始/结束时间；选择后在同一右栏打开该子智能体的只读会话 Viewer，呈现其文字与工具时间线 | 主轨迹中的子智能体行、对话中的子智能体行、右侧 `+` 菜单 |

文件、浏览器及已打开的文件标签照常共存。右栏只有页头的一层可关闭标签条，不在 Viewer 内容里复制标签条。点击某个子智能体时，打开或聚焦以 `childSessionId` 为身份的标签；回到「子智能体」列表不丢失其滚动位置。子任务未产生可读会话时显示状态和最后一次进度，不伪造内部事件。

轨迹默认右栏可展示压缩的「轮次 / 调用」概览和可读行；沿用现有右栏放大按钮与拖拽宽度。放大后呈现参考图完整的「时长 / 轮次 / 调用」三视图概览带：输入、模型、工具与上下文分层着色，选择一个轮次或色块会定位到下方对应行。概览与逐行记录消费同一会话投影，不能出现不同的计数或顺序。收回窄栏后保留当前会话、视图、筛选与滚动锚点；高密度刻度随宽度简化，不横向压缩文字。

生成图保留了四列关系与 Yuanpu 输入卡片，但图像放大像素不能直接用作 CSS 尺寸。轨迹中所有文字、路径、模型、token 和事件类型组合均为示例，不表示真实调用已经发生。

助理对话与工作对话共用的输入区可复用模型/上下文控件，但运行数据必须按各自会话与宿主隔离。工作对话现有「动态」「运行」替换如上；助理当前的 `AssistantHome` 仍是默认右侧内容，若在助理对话打开运行 Viewer，应作为助理会话自己的标签，不把工作会话或记忆内容混入。

## 对话中的运行过程

提交后在原消息流内建立一条与 `runId` 绑定的助理消息。它从第一段可显示文字开始流式更新；还没有文字时显示当前已观测阶段。紧接消息正文是一行「运行过程 · N 个事件」，运行中默认展开最近若干条，完成后默认折叠，用户可随时展开。每个过程行是原有消息排版中的轻量单行：图标、类型、短摘要、状态；不增加大型任务卡，不预测未来步骤。长名称截断，悬停或展开可看安全详情。

同一工具/消息步骤在对话与右侧轨迹中有可关联的身份。点击过程行会打开「运行轨迹」并定位到当前会话该步骤所在轮次；子智能体行打开对应子会话 Viewer。过程行可随事件更新为完成、失败、等待授权、取消或中断。终态只更新这条消息的正文与状态，不能再次追加一条重复回复；取消和错误也保留已观察到的文字与过程，并沿用现有恢复入口。

| 类型 | 对话紧凑标签 | 右侧详情的来源与范围 |
| --- | --- | --- |
| 思考 | `思考 · 正在梳理实现路径` | 仅展示明确可供用户查看的阶段摘要或运行时状态，不暴露模型私有推理链。可显示耗时。 |
| Skill | `Skill · frontend-design` | 显式技能启用/调用事件；仅仅加载技能清单或模型文字提到技能不算调用。 |
| Web 搜索 | `Web 搜索 · 查询 Pi telemetry` | 已识别的 `web_search`/`fetch_content` 调用，显示查询/站点的安全摘要与完成状态。 |
| 文件 | `读取 · chat.tsx`、`编辑 · chat.tsx` | 文件工具开始/结束；路径展示可打开的工作区相对路径，写入可链接现有文件/替换效果 Viewer。 |
| 代码 | `代码执行 · TypeScript 检查` | 专用代码运行工具的显式类型；Bash/终端仍单列，不能仅凭标题推断。 |
| Bash | `Bash · pnpm check` | 命令摘要、耗时和退出状态；原始 stdout/stderr 只在已有授权与脱敏规则允许时展开。 |
| MCP | `MCP · 检索文档` | 能力源/服务/工具的标识及调用状态，不直接显示凭据或完整参数。 |
| 通用工具 | `工具调用 · get_context_usage` | 未命中专门类型的工具仍有统一行，不静默丢失。 |
| 子智能体 | `子智能体 · 界面审查` | 父运行记录启动/进度/完成，点击进入独立 Viewer；父轨迹不内嵌整个子会话。 |

审批、压缩上下文、重试、断线恢复和运行终态也占独立系统事件行；类型筛选可隐藏，不能改变真实顺序或结果。相同文件连续读取可在对话里视觉归组，但右侧保留各次调用与时间。

## 输入区与上下文

输入卡片沿用现有尺寸和左侧 `+`、权限控件；右下依次是模型选择、上下文圆环、发送/停止。模型菜单从当前已配置的 provider/model 目录读取，模型与思考强度为两个层级；选择作用于该会话的下一次提交，在发送瞬间冻结到运行记录。正在执行的 run 不受后续切换影响；工作与助理会话选择独立，不能通过改写全局模型设置来实现会话选择。不可用模型给出可恢复提示，当前输入保留。

圆环显示当前会话上下文占用百分比，点击在输入区上方展开**仅有上下文详情**的轻量面板：已用/窗口总量、彩色分段条和系统提示词、工具定义、技能/注入内容、对话消息、其他分类数字。面板底部只有一个「打开运行轨迹 →」按钮，点击后关闭弹层并打开右侧当前 Pi Session 的轨迹 Viewer；弹层不再有「运行轨迹」页签或事件预览。界面直接显示占比与数字，不写“估算”。数据口径是当前有效上下文与模型窗口，不是会话累计计费 token。运行时从当前 Pi 会话的 `getContextUsage()` 与实际请求构成收集；分类缺数时该项显示 `—`，压缩后总占用未知时圆环也显示 `—`，直到下一次可用测量，不能补造数字。面板与模型菜单互斥；键盘、触屏和窄宽度均可关闭。

## 会话轨迹的数据与进程边界

**Pi Session 是轨迹的历史权威。** 工作对话已有不可复用的 Pi session ID。`SessionManager.getBranch()` 返回当前活动分支，包含带 `id`、`parentId`、`timestamp` 的 `message`、`model_change`、`thinking_level_change`、`usage`、`compaction`、`custom_message` 等条目；助手消息中还有工具调用块，工具结果是单独的消息。现有 `readYuanpuChatTranscript` 只投影可见聊天文字，不足以生成参考图式的轨迹。因此在 Yuanpu 适配层新增按工作会话授权的 **SessionTrajectory 投影**，从活动分支读取历史、分页生成概览和详细行；不把整份 Pi Session 复制成第二套业务日志，也不直接把磁盘路径暴露给 renderer。跨多轮的会话顺序取自 Pi 分支，`AgentRunRecord` 只补各次执行状态与归属。

```text
绑定的 Pi Session 活动分支 ───────────────┐
Pi 实时事件（增量、工具、entry_appended） ├─> Yuanpu SessionTrajectory 投影
能力源/Skill/子智能体显式事件 ────────────┤       ├─> 历史快照 + 游标增量 ─> Electron preload ─> 中央对话/右侧 Viewer
Telemetry span（耗时与父子关系） ──────────┘       └─> 会话概览：时长 / 轮次 / 调用
```

右侧逐行记录按**当前会话活动分支**排布，而不是选「本次运行」。轮次由用户输入到对应助手收束划分；每行保留角色/类型、时间、摘要、状态。工具行默认展示名称和短入参 → 短结果，展开后查看该会话已记录的详细调用与结果；长文本设上限并提供明确截断状态，敏感字段按现有授权/脱敏策略处理。失败结果以实际错误状态突出。压缩、模型切换、重试、授权、子智能体启动/结束作为上下文或操作标记插入相应位置。可展示的“思考”限于明确面向用户的内容或阶段摘要，不读取隐藏推理。

正在运行的步骤可能尚未成为 `SessionEntry`：用 `session.subscribe` 的文字增量、工具开始/结束、`entry_appended` 形成临时行；条目落盘后以 Pi entry ID/工具调用 ID 对齐，原位替换临时行，不在尾部再追加副本。历史行使用 Pi entry ID，实时流使用会话 ID + 单调游标；`runId` 用来定位该行属于哪次执行，不能充当整条轨迹的主键。重连先取活动分支快照，再按游标接增量；旧分支、其他工作会话和子会话不得混入。会话很长时按轮次分页、虚拟滚动和概览聚合，搜索仍能定位未渲染的历史行。

`@earendil-works/pi-telemetry` 只有 callback span 契约和进程内参考实现；它适合补足父子关联、状态和耗时，但没有可直接用于 UI 的持久实时轨迹，也不替代 Pi Session 条目。telemetry 不记录 prompt、完整工具入参/输出、密钥或私有推理；轨迹详情从按会话授权的 Pi 投影读取。无法恢复的历史耗时留空，不用时间戳差值伪装成模型请求时长。Pi 同步包不因本设计直接修改。

当前工作子智能体管理器已有运行 ID、状态、子会话 ID 和进度回调，但子会话 `session.subscribe` 尚未向宿主投影，需从该边界补齐。助理的委派来自独立的 `yuanpu-assistant`，通过同一显示协议做单独适配，不与工作 Agent runtime 混用存储或会话。

## 状态与验收

| 场景 | 应见结果 |
| --- | --- |
| 提交后模型持续输出 | 第一段文字到达即出现并增长；过程逐项更新，终态无重复回复。 |
| 同一会话连续三轮 | 右侧按 Pi 活动分支完整显示三轮用户、助手和工具过程；顶部轮次概览跳转到对应行，刷新后顺序一致。 |
| 工具、代码、MCP、Skill、Web 搜索 | 仅真实发生的事件按稳定类型显示；开始、完成、失败有对应状态，未知工具归「工具调用」。 |
| 多个子智能体并行 | 父消息与轨迹各有独立摘要；右侧列表可分别打开只读子会话过程，不串流。 |
| 等待授权、取消、失败 | 已产生的文字与轨迹保留；状态和下一步清晰，取消后的迟到事件不复活运行。 |
| 窗口/订阅重连 | Pi 活动分支快照与实时游标重新拼接，无漏项、乱序或重复行；临时行落盘后原位转为历史行。 |
| 上下文弹层 | 只有用量分类和「打开运行轨迹」按钮；点击后打开当前会话的右侧 Viewer，不出现轨迹页签或事件预览。 |
| 切换模型或压缩上下文 | 模型只影响下次运行；圆环与分类按当前口径刷新，未知量显示 `—`。 |
| 切换工作会话或打开文件 | Viewer 按会话隔离，文件/浏览器标签可继续使用；关闭右栏不停止 Agent。 |
| 390–1440 px、键盘和读屏 | 窄屏右栏成为可关闭抽屉；事件类型/状态有文字标签与可达焦点。 |

实现应限制在中央消息、输入卡片右下和右栏的单层标签/body 三块；不得改变左侧工作树、顶栏或面板比例。视觉样例不代替功能验收。
